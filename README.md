# 多语手账的公开译文与人物匿名化

合成访客手账展务记录采用 UTF-8 编码，人物、单位和记录均为合成内容。

| 资料 | 字段 |
| --- | --- |
| `资料/手账.json` | `id`、`page`、`signature`、`language`、`text` |
| `资料/释译.json` | `id`、`source`、`language`、`text` |
| `资料/同意登记.json` | `id`、`contributor`、`source`、`scope`、`text` |
| `展区.json` | `id`、`medium`、`languages`、`audience` |

每份资料是 JSON 数组。记录中的字段值按来源原样保留为字符串，逗号和顿号可以属于字段内容。资料中可能有转述、不同的拼写以及较晚录入的更正。数字及日期在这些文件中沿用各资料自身的含义；原文位置以记录编号及文本范围定位。

`readMaterials` 只读取资料，不解析其中的正文含义。

## 展务决定（仅展务审阅）

`展务/` 下的文件是人工核对结论，公开输出不直接引用其原始内容：

| 文件 | 作用 |
| --- | --- |
| `人物对齐.json` | 同一访客的中文与拉丁字母写法（Mei/May Lin、小伊/Yi）。只用于称呼对齐，**不扩大许可范围** |
| `词条对齐.json` | 跨语言词条与跨页引用核对（如 b1 借用 b2 的“天光正好”） |
| `组合线索.json` | 单条匿名后不明显、并列可重新指认同一人的线索簇及处置 |
| `重新认证.json` | 撤回许可后、由另一条原文独立支持译文时的重新认证登记 |

## 工具模块（`src/`）

| 模块 | 职责 |
| --- | --- |
| `text-utils.js` | 分句与字符范围定位、范围合并、遮蔽 |
| `person-registry.js` | 人物/称呼对齐、签名拆词、正文称呼定位 |
| `references.js` | 本页表达 vs 跨页引用、同行者/地点/职业线索、译文锚点对齐与归属核对 |
| `consent.js` | 同意登记解析为按元素（祝词/昵称/同行者/地点/语言）的许可，处理撤回改定 |
| `curation.js` | 按展区生成公开/私人片段，执行语言、许可、引用、抹除、独立性、组合线索规则 |
| `versioning.js` | 当前版与退役版；退役版仅展务可见并保留当时决定依据 |
| `inquiry.js` | 来宾查询（场地/批准范围/展示状态）、在线定位、展务审阅视图 |
| `pipeline.js` / `cli.js` | 端到端流水线与命令行 |

### 片段公开判定顺序

1. 展区语言覆盖片段语言；
2. 该来源在本展区有当前有效同意（许可不跨页、不随人物合并扩大）；
3. 跨页引用须由被引用记录自己的同意覆盖本展区，否则整条转私人并标注误归风险；
4. 元素级许可：被 deny 或未获准的昵称/同行者/职业/地点线索予以抹除；
5. 抹除后若只剩虚词骨架、读者会误归给另一人，则整条保留私人记录；
6. 译文须有明确可译许可且无归属错误；原来源撤回时只接受登记在案、状态有效的重新认证；
7. 组合线索分析：同一线索簇在两条及以上公开项并列时按展务决定撤下，改用替代解释或窄化祝愿。

## 命令

```sh
npm ci --offline --ignore-scripts --no-audit --no-fund
npm test          # 37 项单元与集成测试
npm run materials # 读取资料并统计数量
npm run build     # 生成公开/退役/审阅输出到 输出/（已 gitignore）
npm run review    # 打印展务审阅报告
node src/cli.js inquiry <记录编号>  # 来宾查询：使用场地、批准范围、展示状态
node src/cli.js locate  <记录编号>  # 在线定位受影响片段与字符范围
```

## 输出结构

```
输出/
  公开/<展区>.json     当前版本的公开片段（含遮蔽文本、字符范围、引用）
  公开/当前.json       当前版本指针
  退役/<版本>/<展区>.json  仅展务：历史版本与当时采用的决定依据
  展务/审阅报告.json    仅展务：私人记录、线索簇、撤回原因、退役版本
```
